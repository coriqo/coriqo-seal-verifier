For examiners and auditors

Check a sealed record yourself.

Drop a Coriqo proof, certificate, bundle or PDF on this page. It checks the signature, the Merkle proof and the timestamp on your computer. The file is never uploaded, and the page makes no network request while it checks. The code is open: verify.js and verify-ui.js.

On your machine

Three commands, then try to break it.

You need Python 3.10 or newer and git. After the first command you can disconnect from the network.

  1. Get the verifier and its one dependency.

    git clone https://github.com/coriqo/coriqo-seal-verifier
cd coriqo-seal-verifier && pip install cryptography

  2. Check the sample record.

    python verify_proof.py testdata/proof.json

  3. Change one character of the sealed event hash and check again. The output shows [FAIL] Merkle inclusion proof and the command exits 1.

    python -c "import json;d=json.load(open('testdata/proof.json'));h=d['leaf_input'];d['leaf_input']=('1' if h[0]=='0' else '0')+h[1:];json.dump(d,open('edited.json','w'))"
python verify_proof.py edited.json
What it checks

What each check means.

Proof fields match the signed checkpoint bodyThe tree root and size the file quotes are the ones the signature covers, not values added later.
Merkle inclusion proofThis event’s hash is one of the events the checkpoint sealed.
Checkpoint signatureThe checkpoint was signed by the key the file names, and none of its bytes have changed since.
Timestamp consistencyThe time the file states matches the time inside the signed checkpoint.
Spec versionThe file names the version of the format it was written to. A verifier refuses a major version it doesn’t implement instead of giving a verdict.

The full rules, written so anyone can build their own verifier, are in SPEC.md.
